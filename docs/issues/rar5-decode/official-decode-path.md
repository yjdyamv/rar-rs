# RAR5 解码路径与官方对拍（未关闭）

> 目标：`Rar723.exe`（WinRAR 7.23 随包的那个 `Rar.exe`），工具 ghlab，项目
> `~/re/proj/ghlab`（该二进制的分析已入库，含 `rar5-filter` / `rar5-decode`
> 两条笔记）。本文件只留结论与锚点，取证过程在提交信息里。

## 已关闭：x86 滤镜（E8/E8E9）

`FUN_140042ce8` 是逆变换，由解码端的「应用已完整滤镜」循环 `FUN_140040f10`
逐条调用（该循环遍历 `ctx+0x8190` 计数的数组，每条 0x20 字节，带
start/length）。 它的语义与 `crates/rar/src/codec/common/filters.rs` 的
`e8_encode` / `e8_decode_in_place` 逐条等价：

| 项         | 官方                                | 我们                         |
| ---------- | ----------------------------------- | ---------------------------- |
| 操作码     | `0xE8`；`!e8_only` 时再加 `0xE9`    | `cmp_mask` = 0xFF / 0xFE     |
| 操作数位置 | `(CurPos + FileOffset) % 0x1000000` | 同（`X86_FILTER_FILE_SIZE`） |
| 步进       | 命中 +5，否则 +1                    | 同                           |
| 下界       | `i < len - 4`（需 5 字节）          | `n < 5` 直接返回             |
| 减法守卫   | `cand >= 0`（有符号视角）           | `addr >= offset`             |

编码侧是 `FUN_14004ac5c`，由写侧 `FUN_140048930` 调用，并顺带写出滤镜记录
（`type` 1=E8 / 2=E8E9、码表 `DAT_1400bb000` / `DAT_1400bb038`、长度字段）。
两个函数共用同一套「虚拟 16 MiB 地址空间」算术，方向只由调用者传入的基址符号
决定（mod 2^32 下加法即减法），所以函数本身与方向无关。

长期规则已并入 [`PITFALLS.md`](../../PITFALLS.md)
的「字节对齐」段（守卫不可去掉、 滤镜是纯函数因而区域可任意重切）。

## 未关闭：4 槽距离缓存

`Repeat` 与距离码 0..3 所用的 4 槽缓存**还没在二进制里定位到**。已知锚点：

- `FUN_1400444a4` 窗口驱动：`ctx+0xe8` 窗口缓冲、`+0x158` 窗口大小、`+0x178`
  位置、`+0x8190` 待应用滤镜计数、`+0xb1d8` 解码状态、`+0xb1c8`/`+0xb1c9` 标志。
- `FUN_1400578e0` LZSS 解码核心：bit reader 在 `param_1+0`/`+8`，约 0x3000 字节
  的栈帧，Huffman 表建在栈上。
- `FUN_140040c8c` 滤镜记录解析：0x20 字节/条，落在 `ctx+0x198`，容量 0x400。
- `FUN_140040f10` 应用已完整滤镜（见上）。

缓存不是 `FUN_1400578e0` 的 `ctx` 位移（它只碰 `param_1+0`/`+8`），所以要么在它
的状态对象里，要么在寄存器驻留的指针上。下一步：在该函数里扫三连移位
（`cache[3]=cache[2]; cache[2]=cache[1]; cache[1]=cache[0]; cache[0]=新值`），
或对它的被调者跑 `ghlab offsets`。

我们的规则仅作对照，且已被经验钉住（官方 UnRAR 能逐字节还原我们的流，含 227 MiB
真实 PE）：`Repeat` → `cache[0]`；码 0..3 → LRU
前移（`dist_cache_touch`）；真距离 → 整体下移、新值进 slot
0（`dist_cache_push`）。
