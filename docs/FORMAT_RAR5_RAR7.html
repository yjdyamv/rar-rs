1 · 心智模型：块流总览

RAR5/RAR7 是一个块流（block stream）格式：一个归档 = 一串首尾相接、无间隙的块。五种块共用同一个外层信封（§2/§4）。

可选 · SFX stub任意长度

自解压模块。起点 = 首个 Rar!\x1a\x07\x01\x00 签名（detect::sfx_offset_of）。

签名 · 8 字节52 61 72 21 1a 07 01 00

Rar! 后接 1A 07 01 00。RAR7 同此签名。

可选 · 归档加密头 0x04-hp

明文写（无 IV）。-hp 分卷的每一卷开头重复此块。

主归档头 · block 0x01归档标志 + Locator

含 VOLUME / SOLID / RECOVERY / LOCKED 标志；extra 区携带 QO/RR 偏移 locator。

文件头 + 数据区 · block 0x02每成员一组，重复 N 次

成员 = 文件头 + 紧跟数据区。数据区是 LZSS+Huffman 流，或（method=0 STORE）原文。压缩成员后跟一组压缩块（§6）。

可选 · QO 服务块 0x03归档尾部

quick-open 缓存：每个文件头的副本，使 listing 为 O(QO) 而非 O(archive)。

可选 · RR 内联恢复记录 0x03QO 之后

GF(2¹⁶) Cauchy 奇偶（§9.1）。-hp / 分卷下不可用。

归档结束头 · block 0x05SKIP_IF_UNKNOWN + 结束标志

块标志写 0x0004；"有无下一卷"放在随后的结束标志 vint 里（见 §4.6 陷阱）。

单卷：上序。多卷：每卷末尾为带 END_FLAG_NEXT_VOLUME 的结束头；-hp 分卷每卷开头重复明文加密头。

2 · 基础编码

2.1 字节序

所有多字节整数（CRC、时间戳、偏移、大小）均为小端。

2.2 vint · 变长整数

每字节 7 数据位（bit 0–6），bit 7 续延（1=还有）。小端序，上限 10 字节；第 10 字节超出 bit 63 的位被忽略。

0 … 1270xxxxxxx（1 字节）
128 … 163831xxxxxxx 0xxxxxxx（2）
…最多 10 字节

⚠ 非规范定宽 vint：WinRAR 7.x 写头部大小等字段用非最简定宽 vint，短值也可能占 9–10 字节。块头 CRC32 必须对磁盘原始 vint 字节 + body 算，而非重编码后的规范 vint；locator 偏移用 vint_fixed5 预分配、close 时回填。

4 · 各块详解

4.1 归档签名

52 61 72 21 1A 07 01 00  —  "Rar!" 1A 07 01 00

RAR7 签名相同。RAR4 及更早（Rar!\x1a\x07\x00 / RE~^）被 rar-rs 明确拒绝。

4.2 主归档头（0x01）

[块类型=0x01][块标志][extra 大小?][归档标志 vint][卷号 vint —— 仅当 VOLUME_NUM][extra 区]

归档标志

0x0001VOLUME分卷集一员
0x0002VOLUME_NUM后随卷号（1 起）
0x0004SOLID固态归档
0x0008RECOVERY含内联 RR
0x0010LOCKED已锁定

Locator 记录（extra type 0x01）

[记录大小 vint][类型=0x01][标志 vint: 0x0001 有 QO / 0x0002 有 RR][QO 偏移 vint][RR 偏移 vint]

偏移相对归档起点（签名之后），固定 5 字节 vint；在 close 时回填（QO/RR 记录起始绝对位置）。

🔧 rar-rs 做法：locator 的 QO/RR 偏移字段用 vint_fixed5 预分配成固定 5 字节，写文件时在对应绝对位置原地回填——偏移在写文件头时尚未知。读端用 main_header_locator_fields 定位这两个 5 字节字段。

4.3 文件头（0x02）

[类型=0x02][块标志][extra 大小?][数据大小?][文件标志][解压大小][属性][mtime 4LE?][CRC32 4LE?][压缩信息][host OS][名字长度][名字 UTF-8][extra 区?]

文件标志

0x0001DIRECTORY目录条目（无数据区）
0x0002TIME_UNIX4 字节 Unix mtime
0x0004CRC324 字节 CRC32
0x0008UNKNOWN_SIZE解压大小未知（流式）

压缩信息 vint · 位布局

bit 0–5version0=RAR5 / 1=RAR7
bit 6solid共享 LZ 窗口
bit 7–9method0=store, 1–5=级别
bit 10–13dictRAR5 4 位幂
bit 15–19dict_fracRAR7 1/32 增量

RAR5 字典 128 KiB << log（≤ 4 GiB）；RAR7 字典 (32+frac) << (power+12)（≤ 64 GiB，见 §11.2）。

4.4 服务块（0x03）

复用文件头外形（type=0x03，名字在名字字段），数据区承载服务负载，extra 区承载 SUBDATA 记录（type 0x07）。rar-rs 支持四种：

名字负载extra SUBDATA块标志
CMT注释文本（数据区，store）无DATA_AREA
QOquick-open 缓存空记录（仅类型字节）DATA_AREA + SKIP_IF_UNKNOWN
RR内联恢复奇偶数据1 字节恢复百分比DATA_AREA + SKIP_IF_UNKNOWN
STMNTFS 备用流内容流名 :nameDATA_AREA + DEPENDS_PREV

QO 负载：每条 [条目 CRC32 4LE][body 大小 vint][body = 条目标志 0][相对偏移 vint][头部大小 vint][文件头原字节]；相对偏移 = QO 起始 − 文件头绝对位置（正值）。

4.5 归档加密头（0x04）

[类型=0x04][块标志=0][加密版本 vint=0][加密标志 vint: 0x0001 密码校验位][强度 1B][盐 16B][12B 密码校验值?]

归档级加密头不含 IV——其后每个块自带 16 字节 IV（§7.2）。-hp 分卷集的每一卷开头重复此明文块（同盐/同校验值）。该头之后所有块为 [16B IV][AES-256-CBC 密文]（zero-fill，§7.2）。

4.6 归档结束头（0x05）

[类型=0x05][块标志=SKIP_IF_UNKNOWN 0x0004][结束标志 vint]

结束标志 0x0001 = NEXT_VOLUME；分卷非末卷写 NEXT_VOLUME，末卷写 0。

⚠ 7-Zip 陷阱（务必照做）：0x0004 是真实的块标志位。若把"结束标志=1"误塞进块标志位，7-Zip 会把它当 EXTRA_DATA，进而把结束标志当 extra 区大小消费掉，多卷解析直接失败。WinRAR 写 SKIP_IF_UNKNOWN（0x0004），rar-rs 同样写这个块标志值，把"有无下一卷"放在随后的结束标志 vint 里。

6.1 压缩块头

[标志 1][校验 1][大小 1–3 LE][块数据]

标志 bit 7=含 Huffman 表；bit 6=末块；bit 5–3=大小字段宽度−1；bit 2–0=末字节有效位−1。校验 = 0x5A ^ 标志 ^ 大小每字节。空成员：单块 0x40。编码器把 LZSS 流切成 ≤ 128 KiB（0x20000）块。

6.2 Huffman 表

每块先写 4 张表，码长 ≤ 15

BC20编码其余表的码长
NC306主符号
DC64 / 80(DCX)距离低位
LDC16大距离低 4 位
RC44过滤器参数

码长串联经 BC 表 RLE（16/17/18/19 带额外位）；BC 码长用 4 位半字节，15 转义零游程。解码用 quick-lookup（2¹⁰）。

6.3 LZSS 主符号（NC 表）

0–255字面量字节
256过滤器标记（§6.6）
257重复匹配（距离缓存 0 号 + 上一匹配长度）
258–261距离缓存索引 0–3 的匹配（长度见后）
262–305匹配，长度槽 = 符号 − 262（§6.4）

6.4 长度解码

slot < 8:  长度 = 2 + slot
slot ≥ 8:  lbits = slot/4 − 1
  base = 2 + ((4 | (slot & 3)) << lbits)
  长度 = base + 读 lbits 位

6.5 距离解码与缓存

slot < 4:  距离 = 1 + slot
slot ≥ 4:  dbits = slot/2 − 1
  base = 1 + ((2 | (slot & 1)) << dbits)
  dbits ≥ 4: 高 (dbits−4) 位直接读，低 4 位用 LDC
  dbits < 4: 直接读 dbits 位
  距离 = base + 上述增量

距离缓存：4 项 LRU。NC 257 与 NC 258–261 读缓存提至队首；新距离压队首。长度奖励：距离 > 0x100 / 0x2000 / 0x40000 各 +1。

6.6 过滤器

[块起始偏移 vint][块长度 vint][过滤器类型 3 位][通道数−1 5 位]

类型 0 Delta / 1 E8 / 2 E8E9 / 3 ARM（仅 Delta 用通道数 1–4）。作用于解压输出区域，可链式；区域上限 0x3FFFF（256 KiB − 1）。类型 4–7 显式报错。

6.7 位序

压缩位流高位在前（MSB-first）逐字节打包；Huffman 码与额外位同序。

7 · 加密

7.1 密钥派生（链式 HMAC-SHA256 KDF）

U₀ = HMAC(password, salt‖BE32(1)); Uᵢ = HMAC(password, Uᵢ₋₁); acc = XOR 累积

单条 HMAC 链共 2^strength + 32 次迭代，XOR 折叠在三个切点取样（数据密钥 / hash key / 校验值）。💡 强度上限 2²⁴（读取侧拒绝防 CPU DoS）；默认 2¹⁵。三段产物来自同一条链。

7.2 文件加密

AES-256-CBC，每文件随机 IV。填充 zero-fill 到 16 字节边界（非 PKCS7，7-Zip 校验全零）；空文件也产生 16 字节密文。流式：IV 链跨分块连续（CbcRangeEmitter），卷大小仍精确。加密成员头 CRC 是密文 CRC；明文 CRC 用 hash-key MAC 保护。

7.3 密码校验值（12 字节）

[0..8) KDF 末段 XOR 折叠 8 字节 · [8..12) SHA-256(前 8 字节)[0..4)

比较为常数时间。无校验值时（flags 无 0x0001）任何密码都"通过"。

7.4 头加密（-hp）

每卷开头写明文归档加密头（无 IV）；其后每块头为 [16B 随机 IV][AES-256-CBC(zero-fill) 密文]。密钥每卷重派（同盐），块 IV 各自随机。🔧 限制（与 WinRAR 一致）：-hp 分卷不能用内联 RR；QO 不与 -hp/分卷组合。

7.5 hash-key MAC

MAC(CRC32) = XOR 折叠 HMAC(hash_key, CRC32_LE) 的 8 个 4 字节块
MAC(hash32) = 同上逐 4 字节折叠成 32 字节

加密 extra 记录标志 0x0002 表示使用。解密端先还原明文 CRC/哈希再校验。

8 · 多卷归档

命名 name.partN.rar（N 从 1）；discover_volumes 自动发现全卷。

卷 1 · part1.rar[加密头?][主头][成员…][结束头 · NEXT_VOLUME]
卷 2 · part2.rar[加密头?][成员…][结束头 · NEXT_VOLUME]
卷 N · partN.rar（末卷）[加密头?][成员…][QO?][RR?][结束头 · 0]

跨卷成员：旧卷写 DATA_CONTINUES 块（非末块头带密文 CRC32），新卷写 DATA_CONTINUE_TO 块（末块头带 MAC 明文 CRC + 完整 extra 区）。支持创建/读取/删除/重命名跨卷成员；不支持分卷 append、分卷锁定、分卷注释、分卷内联 RR（官方 rar 同样拒绝）。恢复卷见 §9.2。

奇偶字节 = 分片字节（16 位符号）按矩阵行线性组合（XOR + 域乘）。修复 = 从幸存分片 + 奇偶解线性方程（含矩阵求逆；奇异报错）。

  • · 编码器状态（EncoderState）跨成员保持：lookbehind 窗口尾部、距离缓存、last-length、Huffman 表——连续压缩成员共享一个 LZ 窗口。
  • · 解码器状态（DecoderState）同理跨成员保持。
  • · 目录 / STORE / 空文件不参与 LZ 窗口（写端重置链）。
  • · solid 分卷同样支持（状态跨卷保持）。

🔧 rar-rs：solid 与多线程压缩互斥（solid 保持串行）；WinRAR 无 rarfiles.lst 时按名字/扩展名启发式排序，rar-rs 按参数顺序（已知小差异，互操作无碍）。

bit 0–5

v50 · RAR5

version=0；DC 64 码；字典 128 KiB << log（≤ 4 GiB）。

v70 · RAR7

version=1；DCX 80 码；字典 (32+frac)<<(power+12)（非 2 的幂，≤ 64 GiB）。

> 4 GiB 字典请求自动选 v70；裁剪落回 ≤ 4 GiB 时自动降级 v50。RAR7 不是独立容器：同一签名、同一信封；逐成员由 version 位区分，一个归档可混合 v50 与 v70 成员。

11.2 大字典编码

dict = (32+frac) << (power+12)
  = (128KiB<<power) + (128KiB<<power)/32 × frac

dict_power 5 位（10–14），dict_frac 5 位（15–19），允许非 2 的幂；编码端以 n ≤ 19 为界（≤ ~126 GiB）。

11.3 DCX 距离表

DC 表从 64 扩到 80 码（HUFF_DCX）：距离槽上限 79 → DBits 38 → 距离可达 ~1 TB。解码用 u64（§6.5 公式不变，slot 上限放宽）。

11.4 与 rars 差异

rars 解析压缩信息 bit 20（rar5_compat）。rar-rs 不写该位、读取忽略（WinRAR 7.23 双向验证通过，不需要它）。其余（v0/v1 字典公式、算法版本上限、solid/方法位）两实现一致。
